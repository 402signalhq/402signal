# Explicit mppx interoperability qualification

This private integration qualifies mppx 0.9.2 for existing x402 V2 exact Base USDC offers. It is not native MPP settlement support and does not change 402Signal's exact routing fee. Dependencies are pinned in package-lock.json.

`prepareBaseX402` accepts an unsigned 402 challenge, the exact HTTPS request URL/method/body, and caller-pinned atomic amount, recipient and payer. GET requests with a nonempty query and empty body may use byte-exact queryless resource metadata; the complete queried URL stays in the reviewed request. POST metadata must match the full URL. It verifies raw JSON before mppx normalization, snapshots those terms, and creates no signature. `createPaymentPayload({authorize})` requires an explicit caller gate that receives the immutable inspection. That gate must verify the route proof and caller policy, acquire a durable one-shot signing claim, and return only a guarded buyer-owned `{address, signTypedData}` account. The guarded account must durably record the exact typed data before delegating to its signer. A successful result contains `paymentPayload` and the PAYMENT-SIGNATURE header; the caller must durably save this complete result before its own single transmission.

The integration never transmits a request. mppx uses `polyfill:false`, an always-failing transport and no automatic policy header. Its fetch wrapper and raw fetch are never exposed. Only explicit EIP-3009 typed-data signing is reachable. Native MPP, permit2, other chains/assets, mppx extensions, ambiguous offers and silently discarded nonempty challenge metadata fail closed. Empty discovery extension markers that mppx omits are explicitly restored unchanged in the final envelope; the full original envelope remains bound in the inspection. Supported offers have a 1–300 second timeout. Preparation expires after at most 60 seconds; this does not renew any original route-proof or authorization expiry.

mppx's x402 signer sets validAfter to signing time minus 600 seconds and validBefore to signing time plus the accepted timeout. This differs from some x402 SDK defaults. A buyer integrating this factory must explicitly permit and validate that profile while persisting the original typed data. No provider acknowledgement or returned credential is proof of onchain settlement.

A prepared instance permits one credential attempt. Cross-process safety comes from the caller's durable claim and signing journal, not this in-memory object. A decline, signing exception, lost response or uncertain transmission must not silently create another credential or a new job identifier. Recovery/reconciliation belongs to the buyer's persisted attempt. The adapter cannot prevent an application from bypassing its own policy or creating a different job.

Tests use actual pinned mppx/viem code, publicly documented synthetic keys, a filesystem journal, and no live provider or payment calls. They cover pure preparation, exact request and offer binding, one-shot concurrent creation, persisted typed-data intent, decline, uncertain signer outcomes, reconstructed journals after response loss, bounded input and no global Fetch mutation. Run `npm ci --ignore-scripts` and `npm test` from this directory in the isolated cloud worker.

Primary API documentation: https://mpp.dev/sdk/typescript/client/Mppx.create
