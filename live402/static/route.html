HTTP integration

This is the paid routing endpoint.

Agents POST /route. An unpaid request returns HTTP 402 with the advertised $0.003 USDC routing authorization. A qualifying live observation settles that fee; a normal typed miss is not settled.

Your buyer keeps its wallet, signing authority and final decision. Seller payment is separate.

Make the result useful before signing

Add "require_route_binding": true for signed evidence of a supported seller request and observed payment offer. Integrate the buyer guard to compare the current offer before your own payment code signs.

Changed terms or expired evidence stop that handoff. They do not undo an already-settled routing fee or guarantee the seller's output.

Supported request shapes and buyer verification

Read the result and the billing state

A completed normal miss returns HTTP 200 with live:false; HTTP 200 alone does not authorize seller payment. On HTTP 503, inspect billing.settlement_state before retrying; never reuse an authorization marked unknown.
