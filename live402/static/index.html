New to agent payments?

An API is a service software calls for search, data or AI models. x402 and MPP let software pay for access as part of a request, in USDC, without an account. 402Signal checks the offer before that payment. Your application keeps its wallet.

Where it fits

One hook in the client you already run.

The hosted API observes the seller and checks its current terms against your rules. The local guard verifies the signed binding before your payment code signs. Your buyer still validates the transaction and its budget; 402Signal never holds keys, signs, pays the seller or retries.

Official x402 client

One onBeforePaymentCreation hook. It pays the checking fee with the same wallet, re-reads the seller's challenge, verifies the receipt with your pinned log key, and aborts a payment whose terms differ from what was verified.

import { signalGuard } from "@402signal/route-guard/x402";

client.onBeforePaymentCreation(
  signalGuard({ fetchWithPayment, trustedLogVkey })
);

mppx (Machine Payments Protocol)

The same guard as an onChallenge hook. A thrown error leaves mppx without a credential, so nothing is signed when the live challenge's terms differ from the verified terms.

import { mppGuard } from "@402signal/route-guard/mpp";

const guard = mppGuard({ fetchWithPayment, trustedLogVkey,
  maxCallAmountAtomic: "1000" });
const mppx = Mppx.create({ methods, onChallenge: guard.onChallenge });
mppx.onChallengeReceived(guard.onChallengeReceived);

The cost of getting it wrong

Small decisions. Real money.

Two illustrations of the problem. They are not customer incidents.

Before payment

A $2,000 job becomes a $20,000 bill.

Your agent plans 100,000 data lookups at two cents each. The seller changes the offer to twenty cents. A buyer that signs the new price without checking its limits turns a $2,000 task into $20,000, before fees.

Keep the limit in trusted buyer code. With the guard in the signing path, changed terms stop the callback instead of quietly becoming a new deal.

Add the pre-sign check
After an unexpected purchase

The agent says it followed the rules. Did it?

The bill is higher than expected and the agent's summary says the limit never changed. A retained 402Signal record lets you inspect the rules actually submitted and the offer that was checked, even if a local report was edited later.

Compare that record with your own policy and payment records. It is evidence of the check, not a recording of every agent action.

Evidence

A record you can check later.

Every bound check returns an Ed25519-signed receipt with an inclusion proof in an append-only log. Checkpoints are anchored on Algorand MainNet with a Falcon post-quantum signature, so later changes to that history become detectable. Keep the private request, receipt and reveal; verify them with the Node guard or the Python package, offline, against a log key you pin yourself.

The anchor protects the checkpoint history. It does not back up private records or make the seller payment post-quantum secure.
