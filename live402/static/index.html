Check x402 and MPP compatibility

New to agent payments?

An API is a service software calls for search, data or AI models. x402 and MPP let software respond to a payment request. 402Signal adds an independent offer check inside your existing payment flow.

Where it fits

Observe the offer. Verify the record. Then decide.

1. Set the buyer rules

Name an endpoint or discover candidates. Set supported limits such as price, network and latency. The hosted API reads current seller terms and returns a qualifying offer or a typed miss.

2. Check before signing

For a signed binding, request require_route_binding. The local guard verifies the evidence against a trusted key and compares the current request and offer. Changed terms or expired evidence stop the configured signing path.

3. Keep the evidence

Store the exact request, raw response, receipt and private reveal in your own storage. Retain your approved policy and wallet records separately. Your buyer still validates transaction effects, budgets and delivery.

Only payments routed through the configured guard are covered. Advisory modes and bypassed signing paths need separate review. Misses, billing and safe recovery.

Integration

Start with the payment client you have.

The official x402 hook needs an existing client, payment-capable fetch and independently pinned log key. It is an addition to your wallet integration.

import { signalGuard } from "@402signal/route-guard/x402";

client.onBeforePaymentCreation(
  signalGuard({ fetchWithPayment, trustedLogVkey })
);

Evidence and trust

A record you can check later.

Bound checks return evidence with an Ed25519-signed checkpoint and inclusion proof. Later Algorand MainNet checkpoints use Falcon authorization to make changes to covered history detectable. They do not make seller payments post-quantum secure.

A signed record is not a guarantee of delivery or output quality, or proof of human approval. You retain the private evidence; the public log cannot restore it. Short-term response recovery is not long-term storage. Signed change alerts require a key and a new observation; a quiet host can remain silent.
