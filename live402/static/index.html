New to agent payments?

An API is a service software calls for search, data or AI models. x402 and MPP let software pay for access as part of a request, in USDC, without an account. 402Signal checks the offer before that payment and records what it saw. Your application keeps its wallet.

Where it fits

One hook in the client you already run.

The hosted API observes the seller and checks its current terms against your rules. The local guard verifies the signed binding before your payment code signs. Your buyer still validates the transaction and its budget; 402Signal only observes, compares and signs the record.

Official x402 client

One onBeforePaymentCreation hook. It pays the checking fee with the same wallet, re-reads the seller's challenge, verifies the receipt with your pinned log key, and aborts a payment whose terms differ from what was verified.

import { signalGuard } from "@402signal/route-guard/x402";

client.onBeforePaymentCreation(
  signalGuard({ fetchWithPayment, trustedLogVkey })
);
x402 buyer guide

mppx (Machine Payments Protocol)

The same guard as an onChallenge hook. A thrown error leaves mppx without a credential, so nothing is signed when the live challenge's terms differ from the verified terms.

import { mppGuard } from "@402signal/route-guard/mpp";

const guard = mppGuard({ fetchWithPayment, trustedLogVkey,
  maxCallAmountAtomic: "1000" });
const mppx = Mppx.create({ methods, onChallenge: guard.onChallenge });
mppx.onChallengeReceived(guard.onChallengeReceived);

Sellers change their terms. Here is what that looked like in September.

Real observations of catalog-listed endpoints, named. Every host is treated the same way and the method is published; a seller cannot pay to be left out.

Price up 67 percent

api.kadec0.xyz/v1/serp

$0.030 USDC on every check from September 1 to September 4. On September 10 the same URL asked $0.050. Same recipient, same chain, no notice a buyer would see. An agent that planned 10,000 searches at the old price was $200 short.

With the hook in the signing path and max_price_usd at the planned price, the check returns a typed miss and the signing callback is never called. With an alert on the host, a signed price_changed event arrives after the observation.

api.agentstools.dev/search

$0.001 through September 4; $0.003 on September 10. Small numbers, large ratio: a budget sized for the September 4 price bought a third of the calls.

A receipt from the earlier check binds the whole challenge. Before signing, the guard compares the new challenge with the bound quote hash and refuses; the earlier qualifying check still cost $0.003 and the new payment cost nothing.

$0.005 at 22:01 UTC on September 2; $0.010 at 02:21 the next morning. The catalog listing still said $0.005 and named a Base recipient, while the live challenge paid a Solana address.

What 402Signal is not

  • Not a wallet, a signer or a payer. It never holds keys, signs, pays the seller or retries a payment. Your buyer still validates the transaction and its budget.
  • Not a promise about the seller. A qualifying offer means the seller answered with valid terms that met your rules at that second; it is not a guarantee of delivery or output quality.
  • Not a recording of every agent action and not uptime monitoring. The record covers the checks that ran; a host nobody checks stays silent.
  • Not the seller's price. Seller charges, deposits, network fees and rent are separate, and a later refusal does not reverse an already-settled check.
