A buyer's view of agent payments

A payment request is not permission to pay.

An agent can find an API and read its price. Its application still needs to decide whether this offer is the one it is allowed to accept.

Discovery is the start, not the decision.

A catalog describes services. It may include a price, supported network and an input schema. Those details help a buyer find candidates, but the seller's current response can differ from the listing.

402Signal keeps advertised metadata separate from observed terms. Free preview finds candidates. A supported live route evaluates the current offer against the requirements submitted by the buyer.

Check the agreement before the signature.

Imagine a buyer planning thousands of requests at two cents each. A twenty-cent offer may still fit the wallet's balance while violating the task's budget. A wallet able to pay is not proof that the operator approved the deal.

Keep enforceable requirements in trusted application code. The local guard compares supported bound evidence with the current request and offer before invoking the buyer's authorization callback. It does not rescue a payment path that bypasses that check.

Multiple offers need an explicit choice too. The native MPP adapters select under pinned requirements and refuse ambiguity, rather than allowing response order to decide.

The price can be smaller than the commitment.

A channel can require more funds up front than one API call consumes. The supported session clients separate the original checked opening from the buyer's continuation policy. Later calls do not make the old observation fresh or silently authorize a top-up.

A group's total, an invoice's price and its job count also need separate interpretation. Each integration guide defines the mechanism it supports; one passing example does not establish compatibility with every merchant.

A missing response leaves a question, not an answer.

A timeout can occur after an economic action. Supported recovery uses the original durable attempt and read-only evidence where available. Uncertainty should not quietly become a new authorization.

Retained evidence helps an operator investigate which requirements reached the check and which terms it observed. Compare it with approved policy and actual payment records. The public transparency log is not a private-record backup or a recorder of every agent action.

Where 402Signal fits

Keep your existing wallet and payment SDK. Add the independent offer check and the supported local verification or buyer workflow when they solve a problem in your application.

A fixed trusted endpoint with an adequate existing client may not need another hosted check. A team integrating several services and mechanisms may value the common decision, evidence and recovery boundaries.
